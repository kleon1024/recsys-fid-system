# Digital Twin v4 Research Basis

Status: supporting evidence only; the executable backlog remains
`docs/plans/digital-twin-v4-execution-plan.md`.

## Evidence map

| Decision family | Primary evidence | Adopted boundary |
|---|---|---|
| Dynamic user world | [RecSim](https://research.google/pubs/recsim-a-configurable-simulation-platform-for-recommender-systems/), [RecSim NG](https://github.com/google-research/recsim_ng), [KuaiSim](https://arxiv.org/abs/2309.12645), [SARDINE](https://arxiv.org/abs/2311.16586), [Sim2Rec](https://arxiv.org/abs/2305.04832) | Separate request/session/cross-session and ecosystem mechanisms; test a family of worlds and reality-gap sensitivity. No simulator is accepted as live truth. |
| External Feed evidence | [KuaiRand](https://arxiv.org/abs/2208.08696), [slate OPE](https://arxiv.org/abs/1605.04812), [cascade DR](https://arxiv.org/abs/2202.01562), [Open Bandit](https://arxiv.org/abs/2008.07146), [Top-K correction](https://research.google/pubs/top-k-off-policy-correction-for-a-reinforce-recommender-system/) | Use only exact logged actions with known propensity, examination semantics, overlap, ESS and weight diagnostics. A guessed position curve is not logging probability. Feed evidence cannot validate Local, retention, supply or LT. |
| Support and shift rejection | [OPE under covariate shift](https://proceedings.neurips.cc/paper/2020/hash/0084ae4bc24c0795d1e6a4f58444d39b-Abstract.html), [uncertainty-aware causal failure detection](https://proceedings.neurips.cc/paper/2020/hash/860b37e28ec7ba614f00f9246949561d-Abstract.html), [conformal prediction under covariate shift](https://proceedings.neurips.cc/paper_files/paper/2019/hash/8fb21ee7a2207526da55a679f0332de2-Abstract.html) | Lack of overlap is an abstention condition, not a threshold-tuning problem. The current robust-distance union is an engineering gate, not a conformal guarantee; later density-ratio/conformal challengers require separate calibration evidence. |
| Semantic challengers | [RecInter](https://aclanthology.org/2025.emnlp-main.956/), [LLM-powered user simulator](https://ojs.aaai.org/index.php/AAAI/article/view/33456), [verifiable user simulation](https://arxiv.org/abs/2606.14474) | LLM agents generate rare semantic scenarios and adversarial cases. Persona, contract, trace and verification remain auditable; token agents never supply high-throughput numeric A/B truth. |
| Full-flow cascade | [RecFlow](https://arxiv.org/abs/2410.20868) | Preserve exposed and unexposed candidates lost at every stage so recall, coarse, fine and mixer failures remain separately diagnosable. |
| Streaming learning and features | [Monolith](https://arxiv.org/abs/2209.07663), [Feast point-in-time joins](https://docs.feast.dev/getting-started/concepts/point-in-time-joins), [Meta event-based sequence features](https://engineering.fb.com/2024/11/19/data-infrastructure/sequence-learning-personalized-ads-recommendations/), [Meta prediction robustness](https://engineering.fb.com/2024/07/10/data-infrastructure/machine-learning-ml-prediction-robustness-meta/) | Use event-time Joiner, active/candidate lanes, served checkpoints and versioned sparse/sequence feature contracts. Gate point-in-time correctness, freshness and training-serving consistency before claiming cadence value. |
| Feed retrieval/ranking | [Instagram Explore](https://engineering.fb.com/2023/08/09/ml-applications/scaling-instagram-explore-recommendations-system/), [sampled softmax](https://arxiv.org/abs/2201.02327), [corrected log-Q](https://arxiv.org/abs/2507.09331), [cross-batch negatives](https://arxiv.org/abs/2110.15154) | Compare multi-source retrieval and model stages on the same corpus, candidate and latency budgets. Persist source-specific proposal probabilities and validate the loss against a small full-softmax oracle; do not assume one log-Q rule is correct for a mixed sampler. |
| Sparse crosses and multi-task ranking | [Wide & Deep](https://arxiv.org/abs/1606.07792), [DCNv2](https://arxiv.org/abs/2008.13535), [MMoE](https://research.google/pubs/modeling-task-relationships-in-multi-task-learning-with-multi-gate-mixture-of-experts/), [video multi-task ranking](https://research.google/pubs/recommending-what-video-to-watch-next-a-multitask-ranking-system/), [ESMM](https://arxiv.org/abs/1804.07931), [Meta multi-stage sequence ranking](https://engineering.fb.com/2026/08/05/ml-applications/from-user-sequences-to-scaling-laws-a-multi-stage-architecture-for-metas-ads-ranking/) | A deeper model is a challenger, not the expected winner. Compare on identical factual candidates, features and budgets; preserve conditional task definitions, heterogeneous action sequences and test negative transfer, calibration and serving cost. |
| Content and cold start | [Instagram new-content recommendation](https://engineering.fb.com/2020/12/10/web/how-instagram-suggests-new-content/), [content-based video recommendation](https://research.google/pubs/content-based-related-video-recommendations/), [multi-surface content co-training](https://research.google/pubs/enhancing-online-ranking-systems-via-multi-surfaceco-training-for-content-understanding/) | Share versioned task-aligned content representations, not response labels; keep cold-start exploration and lifecycle ownership explicit. |
| Creator ecosystem and posting | [content generation/consumption co-optimization](https://research.google/pubs/co-optimize-content-generation-and-consumption-in-a-large-scale-video-recommendation-system/), [participation optimization](https://research.google/pubs/optimizing-for-participation-in-recommender-system/), [ecosystem modeling](https://research.google/pubs/modeling-recommender-ecosystems-research-challenges-at-the-intersection-of-mechanism-design-reinforcement-learning-and-generative-models/), [provider-aware simulation](https://research.google/pubs/towards-content-provider-aware-recommendation-systems-a-simulation-study-on-interplays-among-user-and-provider-utilities/) | Model sparse proxy intent, qualified supply and creator response separately from passive consumption; declare interference and long-horizon assumptions. |
| Overlapping experiments | [overlapping experiment infrastructure](https://research.google/pubs/overlapping-experiment-infrastructure-more-better-faster-experimentation/), [symbiosis bias](https://research.google/pubs/reducing-symbiosis-bias-through-better-ab-tests-of-recommendation-algorithms/), [network experiment design](https://research.google/pubs/designing-ab-tests-in-a-collaboration-network/) | Namespace ordinary parameter tests; use data-diverted, clustered or user-corpus co-diverted designs when shared learning data or ecosystem interference contaminates treatment. |
| Value, long-term measurement and slate policy | [short-versus-long-term experiments](https://research.google/pubs/focus-on-the-long-term-its-better-for-users-and-business/), [long-term revisit surrogates](https://research.google/pubs/surrogate-for-long-term-user-experience-in-recommender-systems/), [multi-task fusion for long-term satisfaction](https://arxiv.org/abs/2208.04560), [long-term ecosystem welfare](https://research.google/pubs/optimizing-long-term-social-welfare-in-recommender-systemsa-constrained-matching-approach/), [diversified recommendations](https://engineering.fb.com/2020/12/17/ml-applications/diversified-recommendations/) | Predict calibrated primitive outcomes, keep author/semantic/format constraints and displaced alternatives observable, and measure LT after randomization. A surrogate needs separate long-horizon validation; a synthetic exchange rate is sensitivity, not truth or a supervised label. |
| Search | [Meta hybrid Groups Search](https://engineering.fb.com/2026/04/21/ml-applications/modernizing-the-facebook-groups-search-to-unlock-the-power-of-community-knowledge/), [e-commerce multi-stage semantic retrieval](https://arxiv.org/abs/2303.11009) | Combine query understanding, lexical and semantic routes, rank/blend and success/reformulation labels. Search owns a conditional sample space. |
| Ads | [Meta Andromeda](https://engineering.fb.com/2024/12/02/production-engineering/meta-andromeda-advantage-automation-next-gen-personalized-ads-retrieval-engine/), [Meta adaptive ranking](https://engineering.fb.com/2026/03/31/ml-applications/meta-adaptive-ranking-model-bending-the-inference-scaling-curve-to-serve-llm-scale-models-for-ads/), [delayed conversion feedback](https://research.google/pubs/handling-many-conversions-per-click-in-modeling-delayed-feedback/) | Retain retrieval and ranking under strict latency, but add auction, pacing, budget, mature delay buckets, advertiser value and Feed guardrails. Model complexity must earn its serving cost. |
| Commerce | [Amazon e-commerce search and recommendation challenges](https://www.amazon.science/publications/challenges-and-research-opportunities-in-ecommerce-search-and-recommendations), [Alibaba behavior-sequence ranking](https://arxiv.org/abs/1905.06874), [Alibaba commodity graph retrieval](https://arxiv.org/abs/1803.02349) | Preserve inventory and shelf/detail/cart/order/payment/refund state, long feedback windows and transaction lineage. Retrieval, sequence ranking and conversion labels remain distinct stages. |
| Local | [local related-business relevance/diversity](https://research.google/pubs/category-driven-approach-for-local-related-business-recommendations/) | Combine geo, category, graph and diversity; nearest distance is not intent. Open-loop Pixel identity and attribution remain explicit synthetic assumptions. |
| Live and heterogeneous formats | [multi-objective live ranking](https://arxiv.org/abs/2608.04455), [multi-surface content co-training](https://research.google/pubs/enhancing-online-ranking-systems-via-multi-surfaceco-training-for-content-understanding/) | Live owns availability, fresh/delayed actions and segment calibration; photo/card/article own format-specific examination. |
| Fleet reliability and scale | [Instagram model registry and stability](https://engineering.fb.com/2025/05/21/production-engineering/journey-to-1000-models-scaling-instagrams-recommendation-system/), [Meta ranking-model robustness](https://engineering.fb.com/2024/07/10/data-infrastructure/machine-learning-ml-prediction-robustness-meta/), [Meta recommendation training systems](https://engineering.fb.com/2026/08/24/networking-traffic/mtia-300-meta-training-chip-built-in-nics/) | Request success is insufficient; registry lineage, per-head calibration/discrimination health, snapshot validation, feature freshness, version compatibility, fallbacks and rollback evidence are required. Profile sparse communication, feature preprocessing and serialization before changing runtimes. |
| Generative challengers | [TIGER](https://arxiv.org/abs/2305.05065), [HSTU](https://github.com/meta-recsys/generative-recommenders), [OneRec](https://arxiv.org/abs/2502.18965) | Introduce generative retrieval/session models only after the conventional cascade has identified samples, budgets and failure ownership. |

## Explicit non-claims

These sources support transferable architecture and evaluation decisions. They
do not reveal a proprietary TikTok DGP, FID layout, Value Tree, COPP formula,
LT exchange rate, creator experiment framework or multi-business causal model.
Synthetic parameters remain versioned assumptions until independently observed.
